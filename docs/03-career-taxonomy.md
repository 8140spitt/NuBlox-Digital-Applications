# 03 — Career Taxonomy

## Source baseline

NuBlox uses the National Careers Service **Construction and the built environment** sector list as the canonical launch taxonomy.

**Verified:** 15 August 2026  
**Profiles:** 84

The source list is an input taxonomy, not the permission model.

## Taxonomy design

Recommended tables:

- `careers`
- `career_aliases`
- `professional_domains`
- `career_domains`
- `capabilities`
- `career_capabilities`
- `professional_packs`
- `pack_capabilities`

A user can hold multiple careers. A career can belong to multiple domains in future even though this baseline assigns one primary domain for product planning.

## Alias rules

Alternative job titles must be stored separately from canonical titles.

Example:

- canonical: `Electrician`
- aliases: `Electrical fitter`, `Electrical technician`, `Installation electrician`

Aliases improve search, onboarding and matching, but must not create duplicate careers.

## Versioning the taxonomy

The career reference dataset must have:

- stable internal ID;
- slug;
- canonical name;
- source;
- source URL;
- source last-verified date;
- active/inactive flag;
- aliases;
- optional source metadata.

Changes in the external career list must not silently remove historical user associations.
