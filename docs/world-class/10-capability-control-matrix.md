# World-Class Capability Control Matrix

**Status:** Governing delivery-control baseline  
**Effective:** 27 August 2026  
**Purpose:** connect NuBlox's 19 native capability domains to enterprise value streams, golden reference journeys, implemented evidence and the World-Class scorecard so delivery sequencing is evidence-led rather than module-led.

## 1. Control principle

This matrix is not a feature inventory and it is not a replacement for the enterprise taxonomy.

It answers one question:

> **Where is NuBlox strong enough to support an end-to-end enterprise outcome today, where is the digital thread incomplete, and what should be strengthened next to move the complete operating system toward world-class maturity?**

The matrix sits between:

- the 29-function enterprise taxonomy — what the enterprise does;
- the 19 native capability domains — what product capability NuBlox owns;
- the nine enterprise value streams — how business outcomes flow end to end;
- the three golden reference journeys — how NuBlox proves integrated product behaviour;
- the bottom-up architecture — how every implementation remains canonical, governed and testable.

## 2. Maturity scale

The code-level capability registry remains authoritative for the current coarse maturity state:

- **Operational** — a meaningful native core is in live product use.
- **Partial** — important native capability exists, but material target-state depth or continuity remains.
- **Planned** — the native domain is recognised and architected, but no material standalone workspace/core has yet been delivered.

This control matrix adds a more demanding World-Class readiness rating:

| Rating | Meaning |
| --- | --- |
| **W0 — Planned** | Target scope exists, but material native execution is not yet delivered. |
| **W1 — Foundation** | Canonical records/services or an initial workspace exist, but the wider business outcome is incomplete. |
| **W2 — Controlled core** | Material native workflow, authority and test evidence exist for a bounded outcome. |
| **W3 — Integrated stream** | The capability participates credibly in an end-to-end value stream with downstream consequences and usable UX. |
| **W4 — World-class** | Deep enterprise + sector capability, digital-thread continuity, strong UX, reporting/intelligence, interoperability and comprehensive proof are all present. |

No domain is declared W4 merely because it is marked `operational` in the capability registry.

## 3. World-Class scorecard dimensions

Each domain is assessed across eight dimensions:

1. **Enterprise depth** — can a sophisticated enterprise genuinely run the function natively?
2. **Built-environment depth** — does it understand construction/property/asset semantics where relevant?
3. **Digital-thread integration** — are upstream/downstream canonical consequences linked without re-keying?
4. **Control** — permissions, state, authority, SoD, audit, evidence, correction/reversal.
5. **Experience** — efficient, contextual, responsive, mobile/field appropriate where required.
6. **Reporting & intelligence** — KPIs, exceptions, drill-through, forecasting and decision support.
7. **Interoperability** — open standards, APIs/events and exchange boundaries where required.
8. **Automated proof** — real database integration, type/static validation and browser-level process evidence.

The matrix below uses **Strong / Developing / Weak / Planned** as directional assessments from current repository evidence. These are product-control judgements, not schema facts.

## 7. Golden-journey dependency map

### Journey A — Win work → deliver → get paid

**Critical domains:** 2, 3, 4, 5, 7, 8, 9, 12, 13, 19.

Highest-leverage gaps:

1. reconcile CRM/commercial/project/procurement/finance into one browser-level proof;
2. deepen estimating/tender governance only where it blocks credible work winning;
3. finish valuation/revenue/invoice/cash/accounting consequence continuity;
4. remove high-frequency UX friction in procurement/cost-control/financials;
5. add management reporting drill-through from enterprise result to project evidence.

### Journey B — Requirement → handed-over operating asset

**Critical domains:** 4, 5, 6, 9, 10, 11, 13, 14, 15, 18, 19.

Highest-leverage gaps:

1. information requirements/responsibilities/deliverable fulfilment;
2. design review + model/object/system/component relationships;
3. product/material/procurement/production lineage;
4. work-package/site/quality/test/commissioning evidence;
5. handover readiness and installed configuration;
6. warranty/maintenance/statutory obligation transfer into operations.

This journey is the strongest candidate for NuBlox's signature digital-thread differentiation.

### Journey C — Operate → maintain → renew/retire

**Critical domains:** 7, 8, 12, 14, 15, 16, 17, 18, 19.

Highest-leverage gaps:

1. handed-over installed asset → maintainable configuration;
2. work-order workforce/parts/contractor/cost consequences;
3. compliance and statutory-inspection evidence;
4. condition/reliability/lifecycle-cost decisions;
5. property/lease/occupancy/FM context;
6. renewal/refurbishment → project delivery → updated asset history.

## 8. Cross-stream bottlenecks

The matrix identifies six bottlenecks that affect more than one journey and therefore deserve disproportionate attention.

### 8.1 Handover / installed-configuration boundary

Today, project delivery and asset maintenance both have native foundations, but their continuity is not yet the primary operational thread. This boundary touches information, site, quality, assets, maintenance, property and sustainability.

**Priority:** very high.

### 8.2 Source-to-pay accounting closure

Procurement has package/RFQ/PO foundations and finance has accounting foundations, but complete supplier invoice/AP/matching/payment/ledger continuity remains material enterprise depth.

**Priority:** very high.

### 8.3 World-class daily UX

The existing UX-friction review shows heavy full-page action cycles and dense workspaces in purchasing, cost control, financial control and assets. Enterprise depth is not credible if users cannot efficiently operate high-volume workflows.

**Priority:** very high.

### 8.4 Governed semantic/reporting layer

NuBlox has canonical data and strong audit/process foundations, but world-class executive/operational reporting requires governed KPI definitions and drill-through semantics across finance, project, workforce, asset and sustainability facts.

**Priority:** high.

### 8.5 People/payroll/project-cost continuity

Workforce, time and project-resource foundations exist. Complete HCM/payroll and the controlled consequence into project actual cost remain a significant enterprise differentiator.

**Priority:** high.

### 8.6 Materials/product/configuration lineage

Materials/inventory and production are planned. Their eventual design must preserve lineage from requirement/design/product specification through procurement/production/installation and asset operation rather than becoming isolated stock/manufacturing modules.

**Priority:** sequence after the canonical Design-to-Asset model is clear.

## 9. Immediate priority order

The control matrix recommends the following order because it improves integrated outcomes rather than just increasing capability count.

### P0 — preserve and prove the strong foundations

- keep identity/authority, Work Kernel, project controls and CRM-commercial progression stable;
- do not duplicate canonical masters to accelerate a new domain;
- keep PR #92 in deliberate reassessment until it fits Journey B and current `main`.

### P1 — improve the operating experience

Execute UX Friction Tranche A:

1. purchasing progressive enhancement + N+1 removal;
2. project cost-control interaction continuity;
3. project financial-control interaction continuity;
4. action latency/error feedback telemetry where appropriate.

### P2 — prove Journey A end to end

Use existing strong foundations to create the first full golden reference proof before broad new-domain expansion.

### P3 — build the Journey B handover junction

Deepen information/design/commissioning/handover enough to create an installed asset and carry maintenance/compliance obligations into operations.

### P4 — deepen enterprise source-to-pay and record-to-report

Complete supplier/AP/payment/ledger and accounting-close continuity so NuBlox becomes more credible as the enterprise system of record.

### P5 — deepen hire-to-retire and asset-to-retirement

Connect workforce/payroll/project cost and maintenance/service/lifecycle decisions into the same governed enterprise thread.

### P6 — introduce planned domains through value-stream need

Materials/inventory, production/fabrication and sustainability should enter the product through Journey B/C and Strategy-to-Performance requirements, not as standalone greenfield modules.

## 10. Evidence rule

A row is upgraded only when repository evidence demonstrates the improvement.

Evidence can include:

- authoritative migration/schema changes;
- canonical domain service/repository implementation;
- permissions/SoD/state/evidence rules;
- real-MySQL integration tests;
- browser-level end-to-end journey proof;
- responsive/field UX evidence;
- reporting/KPI drill-through;
- API/open-standard/event interoperability;
- architecture/ADR documentation.

A route, table, migration count or test count alone does not advance World-Class readiness.

## 11. Update discipline

For every material capability PR:

1. identify the value stream(s) strengthened;
2. identify the golden journey(s) strengthened;
3. state the canonical records and consequences affected;
4. state which scorecard dimensions improve;
5. provide the evidence that justifies any matrix maturity change;
6. update this matrix when the improvement is material.

This turns the matrix into an executable product-control artefact rather than a static assessment.
